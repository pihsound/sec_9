1
보안 운영체제 (Secure OS) 개요
★★★ 2022 국가직 출제
보안 운영체제 정의

보안 운영체제(Secure OS)는 기존 운영체제에 내재된 보안상의 결함으로 인한 각종 침해로부터 시스템을 보호하기 위하여, 운영체제 내에 보안 기능을 통합시킨 보안 커널(Security Kernel)을 추가적으로 이식한 운영체제. 보안 커널을 통하여 사용자의 모든 접근 행위가 안전하게 통제됨.

2
참조 모니터 (Reference Monitor)
★★★ 2024 국가직 출제
참조 모니터 정의

참조 모니터(Reference Monitor)는 주체(Subject)와 객체(Object) 사이의 모든 접근을 통제하는 추상적인 기계(Abstract Machine). 불법적인 접근이나 자료를 막기 위하여 주체가 객체에 접근하기 위한 장치. 특정 주체가 특정 객체에 접근할 수 있는지 확인하는 기능을 하는 안전한 운영체제의 핵심 보안 모듈.

1
격리성 (Isolation) — 주체와 객체의 부정 조작 불가
참조 모니터에 대한 부정 조작이 없어야 한다. 참조 모니터가 무결하게 동작할 수 있도록 격리(완전히 보호)되어야 한다.
2
완전성 (Completeness) — 항상 호출
참조 모니터는 항상 호출되어야 한다. 모든 접근 시도에 대해 시행되어야 하고 회피하는 것이 불가능해야 한다.
3
검증 가능성 (Verifiability) — 소규모·분석 용이
참조 모니터는 검증이 용이하도록 충분히 소규모(Small Enough)이어야 한다. 충분한 분석, 시험, 증명이 가능해야 한다.
⚠함정 ★★★ — 참조 모니터 특성 오답 (2024 국가직 문8)
"참조 모니터는 모든 주체 간 상호 접근통제를 담당하는 추상적인 기계이다." → ✗ 오답

참조 모니터는 주체↔객체 간 접근통제를 담당. "주체 간(주체↔주체)" 접근통제는 틀린 설명. 주체가 객체에 접근하는 것을 통제하는 역할.

"보안 매개변수 설정 등과 같은 다른 보안 메커니즘과 데이터를 교환하면서 상호 작용을 한다" → ✗ 오답

참조 모니터는 다른 보안 메커니즘과 데이터 교환을 하지 않음. 독립적으로 격리(Isolation)되어 동작하는 것이 핵심 특성.

3
TCB (Trusted Computing Base) — 신뢰 컴퓨팅 기반
★★★ 2022 군무원 출제
TCB 정의

TCB(Trusted Computing Base)는 컴퓨터 시스템(하드웨어, 펌웨어, 소프트웨어) 내의 모든 보호 메커니즘의 총체. 신뢰성 있는 컴퓨팅을 위한 기본 환경 제공. 보안 커널은 TCB의 핵심 구성 요소. 운영 TCB는 기본적인 보호 환경을 구축하고 신뢰성 있는 시스템에 필요한 부가적인 사용자 서비스를 제공.

TCB와 참조 모니터, 보안 커널의 관계: 참조 모니터는 개념(Concept), 보안 커널은 참조 모니터를 구현한 것, TCB는 보안 커널을 포함한 시스템 전체의 보안 메커니즘이에요.

보안 커널 = 참조 모니터 개념을 구현한 TCB의 하드웨어·펌웨어·소프트웨어 요소. 보안 커널은 모든 접근 요청에 대해 검사하여야 하며, 변경으로부터 보호되고 검증 가능하여야 한다.

TPM (Trusted Platform Module): 신뢰 컴퓨팅 그룹(TCG)에 의해 산업체가 개발한 개념. 신뢰를 위한 하드웨어·펌웨어에서 동작하는 하드웨어 모듈. 개인용 컴퓨터 메인 보드, 스마트 카드 등에 내장. 인증된 부팅(Authenticated Boot), 증명(Attestation), 봉인(Sealing) 기능 제공.
4
보안 시스템 설계 7원리
★★
1
소규모화 (Economy of Mechanism)
보안 메커니즘은 가능한 소규모로, 단순하며 간결하여야 한다. 보안 메커니즘에 대한 충분한 분석, 시험, 증명이 가능해야 한다.
2
보안 경제성 (Fail-safe Defaults)
접근에 대한 기본 결정은 접근 거부(Denial)이어야 한다. 허가가 있어야만 접근을 허용해야 한다.
3
개방형 설계 (Open Design)
보안 메커니즘은 비밀로 유지하는 것에 의존하지 말고, 공개적으로 설계하여야 한다. 개방형 보안에 대한 많은 검토가 가능하도록 하여 보안에 대한 공개적 검증 가능.
4
완전한 조정 (Complete Mediation)
모든 접근은 완전히 통제되어야 한다. 직접적인 접근이나 접근 통제를 교묘히 우회하려는 접근 모두 통제되어야 한다.
5
최소 권한 (Least Privilege)
접근에 대한 기본 허용은 최소 허용이어야 한다. 작업에 필요한 최소한의 권한만 부여하여야 한다.
6
권한 분리 (Separation of Privilege)
접근에 대한 권한은 2개 이상의 조건을 충족하여야 한다. 단일 보안 완전 통제가 되지 않도록 한다. 물리적·시간적·논리적 분리 포함.
7
최소 공통 메커니즘 (Least Common Mechanism)
공유되거나 공통적인 접근 경로를 최소화한다. 사용 용이성을 위해 보안을 희생하면 안 됨.
1
Windows 인증 구조 — LSA · SAM · SRM
★★★ 매년 출제
Windows NT 인증 구조 핵심

Windows NT 운영체제의 인증 과정에서 가장 중요한 구성요소는 LSA(Local Security Authority) · SAM(Security Accounts Manager) · SRM(Security Reference Monitor). Winlogon → LSA → SAM → SRM 순서로 인증이 이루어짐.

🔐 LSA (Local Security Authority)
역할: 모든 계정의 로그인에 대한 검증을 하고 시스템 자원 및 파일 등에 대한 접근 권한을 검사.
범위: 로컬, 원격 모두에 해당됨.
기능: 이름과 SID를 매칭한다. SRM이 생성한 감사 로그를 기록하는 역할.
위치: 사용자 모드(User Mode)에서 동작하며 로컬 보안 정책을 집행.
🗄 SAM (Security Accounts Manager)
역할: 사용자/그룹 계정 정보에 대한 데이터베이스를 관리.
기능: 사용자의 로그인 입력정보와 SAM 데이터베이스 정보를 비교하여 인증 여부를 결정.
저장: 로컬 주체 및 그룹 관련 보안 정보 및 계정 데이터를 저장하는 DB.
🛡 SRM (Security Reference Monitor)
역할 ①: SAM이 사용자 계정과 패스워드 일치 여부를 확인하여 알리면 SRM은 사용자에게 고유의 SID(Security Identifier)를 부여.
역할 ②: SID에 기반하여 파일이나 디렉터리에 대한 접근 허용 여부를 결정하고 이에 대한 감사 메시지를 생성.
위치: 커널 모드(Kernel Mode)에서 실행되는 접근 통제 임무 수행.
구성요소핵심 기능동작 모드암기 키워드
LSA로그인 검증, 시스템 자원 접근 권한 검사, SID 매칭, 감사 로그 기록사용자 모드로그인 검증, 로컬 보안 정책 집행
SAM사용자/그룹 계정 DB 관리, 로그인 정보↔DB 비교로 인증 결정사용자 모드계정 DB 관리, 인증 결정
SRMSID 부여, 파일/디렉터리 접근 허용 결정, 감사 메시지 생성커널 모드SID 부여 · 감사 메시지
⚠함정 ★★★ — LSA·SAM·SRM 역할 혼동 (2015·2019·2022 국가직, 경찰 반복)
"SAM은 보안 토큰 발급과 저장 등을 수행한다" → ✗ 오답 (2019 국가직)

보안 토큰(SID) 발급 = SRM. SAM은 계정 DB 관리 및 인증 결정만. "토큰 발급"이라는 키워드 → SRM.

"SRM은 로컬 컴퓨터상에서 보안을 제어함으로써 특권 컴포넌트들과 사용자 모드에서 동작하는 서브시스템에 보안 서비스를 제공한다" → ✗ 오답

이것은 LSA의 설명. SRM = 커널 모드에서 실행. LSA = 사용자 모드에서 로컬 보안 정책 집행.

SID (Security Identifier) — 보안 식별자
★★
S-1-5-21-2823624781-484892517-3265479878-500
S (수정자)특정 SID가 수정된 SID인지 여부를 나타냄. 항상 "S"로 시작.

유닉스/리눅스 파일 권한 체계
★★★ 매년 출제
파일 권한 구조

유닉스/리눅스에서 파일이나 디렉터리에 대한 접근 권한은 ls -l 명령으로 확인. 권한은 소유자(User)·그룹(Group)·기타(Other) 3범주, 각 범주에 읽기(r=4)·쓰기(w=2)·실행(x=1) 3가지 권한으로 구성. 첫 번째 문자는 파일 유형(d=디렉터리, -=일반파일, l=링크).

ls -l 출력: d rwx | r-x | r-- ← 디렉터리 / 소유자 rwx / 그룹 r-x / 기타 r--
8진수 표현: 755 ← 7(rwx=4+2+1) / 5(r-x=4+0+1) / 5(r-x=4+0+1)
권한기호값파일에서디렉터리에서
읽기 (Read)r4파일 내용 읽기디렉터리 내 파일 목록 보기
쓰기 (Write)w2파일 내용 수정파일 생성·삭제 (x 권한도 필요)
실행 (Execute)x1프로그램 실행디렉터리 이동(cd)
없음-0해당 권한 없음해당 권한 없음

i-node (아이노드)
★★ 2024 국가직 출제

i-node(Index Node)는 유닉스 파일 시스템에서 각 파일과 디렉터리에 대한 메타데이터를 저장하는 자료구조예요. 중요한 것은 i-node에는 파일명이 포함되지 않는다는 점이에요. 파일명은 디렉터리에 별도로 저장되고 i-node 번호와 연결돼요.

i-node에 저장되는 정보저장 안 되는 정보
파일 유형(일반/디렉터리/링크 등), 접근 권한(rwxrwxrwx), 소유자(UID), 소유 그룹(GID), 파일 크기, 링크 수, 접근·수정·변경 시간, 데이터 블록 포인터파일 이름(File Name) — 디렉터리에 별도 저장

특수 접근 권한 3종 — SetUID · SetGID · Sticky bit
★★★ 매년 출제

SetUID 4xxx
(chmod 4754)		 소유자 실행 위치에 s
예: rws r-x r--		 SetUID가 설정된 파일을 일반 사용자가 실행하면 해당 실행 동안 파일 소유자의 권한으로 실행. 실행이 끝나면 다시 일반 사용자 권한으로 복귀. passwd 명령(root 소유+SetUID → 일반 사용자도 /etc/shadow 수정 가능). 보안 취약점: 불필요한 SetUID 파일 = 백도어·버퍼 오버플로 공격에 이용.
SetGID 2xxx
(chmod 2754)		 그룹 실행 위치에 s
예: rwx r-s r--		 SetGID가 설정된 파일을 실행하면 해당 실행 동안 파일 소유 그룹의 권한으로 실행. 실행 후 원래 그룹으로 복귀. 그룹 소유로만 접근 가능한 리소스에 일반 사용자가 접근할 수 있도록 허용.
Sticky bit 1xxx
(chmod 1755)		 기타 실행 위치에 t
예: rwx r-x r-t		 Sticky bit가 설정된 디렉터리에 파일을 생성하면 해당 파일은 생성한 사람의 소유가 되며, 오직 소유자와 슈퍼유저(root)만 파일 삭제·변경 가능. 다른 사람은 삭제·수정 불가. /tmp 디렉터리에 설정. 공유 디렉터리에서 타인의 파일 삭제 방지.
특수 권한 chmod 명령 예시 (암기)
chmod 4754 file→ rws r-x r-- (SetUID = 4xxx)
chmod 2754 file→ rwx r-s r-- (SetGID = 2xxx)
chmod 1755 dir→ rwx r-x r-t (Sticky = 1xxx)
⚠함정 ★★★ — SetGID chmod 번호 혼동 (2022 군무원)
"SetGID 명령은 chmod 명령에서 'chmod 1755 setgid_program'과 같이 1000번대 인자를 주어 설정할 수 있다" → ✗ 오답

SetGID = 2xxx (2000번대). 1000번대(1xxx) = Sticky bit. 각 번호 암기: 4=SetUID / 2=SetGID / 1=Sticky.

2
umask — 기본 권한 마스크
★★★ 매년 출제
umask 정의

umask(User file creation mode MASK)는 파일이나 디렉터리 생성 시 부여되는 기본(디폴트) 권한을 결정하는 마스크. 파일 기본 최대 권한 = 666, 디렉터리 기본 최대 권한 = 777. 실제 권한 = 기본 권한 - umask.

umask 022 → 파일 666 - 022 = 644 (rw-r--r--) 소유자: 읽기+쓰기 / 그룹·기타: 읽기
umask 022 → 디렉터리 777 - 022 = 755 (rwxr-xr-x) 소유자: 모든 권한 / 그룹·기타: 읽기+실행
umask 133 → 파일 666 - 133 = 644 (rw-r--r--) 소유자: rw / 그룹·기타: r
umask 077 → 파일 666 - 077 = 600 (rw-------) 소유자만 읽기+쓰기
핵심 공식: 파일 실제 권한 = 666 − umask / 디렉터리 실제 권한 = 777 − umask. umask 기본값은 보통 022. umask 명령어로 변경 가능.

★★★ 매년 출제
/etc/passwd 형식

root : x : 0 : 0 : root : /root : /bin/bash

① 사용자 계정 이름 | ② 패스워드(x=shadow에 암호화 저장) | ③ 사용자 UID(root→0) | ④ 사용자 소속 그룹 GID(root→0) | ⑤ 사용자 정보(이름·연락처 기입란) | ⑥ 사용자 계정 홈 디렉터리 | ⑦ 로그인 시 선택한 사용자의 셸

② 필드의 'x'는 shadow 패스워드 시스템에 의해 /etc/shadow에 암호화된 형태로 저장되어 있음을 의미해요. 과거에는 passwd 파일에 직접 암호화 패스워드를 저장했지만, 보안상 이유로 shadow 파일로 분리됐어요. 일반 사용자에게는 /etc/shadow 읽기 권한 없음.

UID: 리눅스에서 관리자는 UID를 0으로 부여. 일반 사용자는 일반적으로 500 이상의 번호를 부여받음. GID도 마찬가지로 관리자 그룹은 0, 일반 사용자 그룹은 그 외의 번호.

/etc/shadow 형식

gong : $uwZvLF9p$YTqglbDFIo : 10917 : 0 : 99999 : 7 : : :

① 사용자 계정 이름 | ② 암호화된 패스워드(salt+해시) | ③ 마지막으로 패스워드 변경한 날짜(1970.1.1 기준 일수) | ④ 변경 최소 일수(0=즉시 변경 가능) | ⑤ 변경 최대 일수(99999=거의 무제한) | ⑥ 만료 경고일수 | ⑦ 비활성화 일수 | ⑧ 만기일 | ⑨ 예약 필드

④ 변경 최소 일수0 = 즉시 패스워드 변경 가능.
⑤ 변경 최대 일수패스워드 변경하지 않고 사용 가능한 최대 일수.
! 또는 * 기호패스워드 미설정 또는 잠긴 계정을 의미.

📄 2019 국가직 7급 · LSA·SRM·SAM 빈칸 (가)(나)(다)★★★
(㉠)은 로컬 사용자에 관련된 보안 정보 및 계정 데이터를 저장하는 데이터베이스이다. (㉡)은 커널 모드에서 수행되며, 사용자나 프로세스가 어떤 객체를 열려고 시도하면 접근 권한을 확인한다. (㉢)는 사용자 모드에서 수행되며, 로컬 보안 정책을 집행하는 책임이 있다.
① ㉠SAM ㉡SRM ㉢LSA
② ㉠SRM ㉡SAM ㉢LSA
③ ㉠SAM ㉡SRM ㉢SID
④ ㉠SRM ㉡SAM ㉢SID
정답 ① — ㉠ 계정 데이터 저장 DB = SAM. ㉡ 커널 모드 + 접근 권한 확인 = SRM. ㉢ 사용자 모드 + 로컬 보안 정책 집행 = LSA. 동작 모드로 구분: SRM만 커널 모드, LSA·SAM은 사용자 모드.
📄 2022 국가직 9급 · 보안 커널 정의 빈칸★★★
보안 운영체제는 기존 운영체제에 내재된 보안상의 결함으로 인한 각종 침해로부터 시스템을 보호하기 위하여 기존의 운영체제 내에 보안 기능을 통합시킨 (가)을/를 추가로 이식한 운영체제이다.

② 접근 제어
③ 신뢰 플랫폼 모듈
④ 하이퍼바이저

📄 2024 국가직 9급 · 참조 모니터 오답★★★
참조 모니터(Reference Monitor)에 대한 설명으로 옳지 않은 것은?

② 참조 모니터 데이터베이스를 참조하여 접근통제를 수행한다.
③ 모든 접근 시도에 대해 시행되어야 하고 회피하는 것이 불가능해야 한다.
④ 보안 매개변수 설정 등과 같은 다른 보안 메커니즘과 데이터를 교환하면서 상호 작용을 한다.
정답 ①과 ④ — ①"주체 간" → ✗, 참조 모니터는 주체↔객체 간 접근통제. ④다른 메커니즘과 데이터 교환 → ✗, 참조 모니터는 격리(Isolation)되어야 함. 일반적 시험 출제: ①번이 오답으로 자주 출제됨.
