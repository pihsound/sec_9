운영체제 개요 및 보안 기능
★★
운영체제 정의

운영체제(Operating System)는 메모리·파일·입출력 장치·프로세서 등과 같은 모든 시스템 자원을 관리하고, 다양한 응용 프로그램 실행을 지원하는 기반 소프트웨어. 운영체제 보안이란 시스템에 대한 위협이나 침입을 방지하는 것을 의미함.

운영체제가 제공하는 3대 보안 기능: ① 메모리 보호(메모리·공유 가능한 입출력 장치·공유 프로그램 보호), ② 접근 통제(서비스·시스템 자원에 대한 접근 제어), ③ 사용자 인증(식별 및 인증). 이 세 가지가 운영체제 보안의 핵심 기능이에요.

2
접근 통제 3종 — DAC · MAC · RBAC
★★★ 매년 출제
DAC
임의적 접근 통제
Discretionary Access Control
시스템 자원에 대한 사용자·개인 또는 그룹을 기반으로 하는 접근 제어 방법.
주체(사용자)가 어떤 접근 권한을 갖는 다른 사용자에게 권한을 양도할 수 있다는 의미.
대표: ACL(Access Control List). 유닉스 기본 권한 체계.
장점: 유연함. 단점: 권한 전파 통제 어려움.
MAC
강제적 접근 통제
Mandatory Access Control
어떤 주체가 특정 객체에 접근하려 할 때 보안 등급(레이블)을 비교하여 높은 보안 수준이 낮은 수준으로 흐르는 것을 통제하는 방법.
모든 객체를 분류하고, 접근하고자 하는 사용자의 허가(Clearance)를 결정하여 제어.
군사·정부 환경에 주로 사용. Bell-LaPadula 모델.
장점: 강력한 통제. 단점: 운영 유연성 낮음.
RBAC
역할 기반 접근 통제
Role Based Access Control
역할(Role)에 의해 접근이 제어되는 방식. 업무에 따라 역할이 구성되고, 접근 권한은 역할에 따라 부여됨.
역할에 필요한 최소 자원만 접근. 업무 변경 시 접근 권한 변경 없이도 역할만 변경하면 됨.
기업 환경에 적합. 관리 편의성 높음.
장점: 관리 용이. 단점: 역할 설계 복잡.
구분DAC (임의적)MAC (강제적)RBAC (역할 기반)
접근 기준주체 신분(개인·그룹)보안 등급(레이블) 비교역할(Role)
권한 양도가능불가역할 단위로 가능
주 사용처일반 유닉스 시스템군사·정부 기밀 시스템기업·조직 환경
대표 모델ACLBell-LaPadulaNIST RBAC
특징유연, 권한 전파 위험강력, 운영 경직관리 편의, 역할 설계 필요
⚠함정 ★★★ — MAC vs RBAC 혼동 (경찰간부·군무원 출제)
"유닉스 운영체제의 기본 접근제어 방식은 MAC" → ✗ 유닉스 기본 = DAC(임의적 접근 통제, ACL 기반)
"부여된 역할에 기반하여 접근이 제어되므로 주로 군사용으로 사용된다" → ✗ 역할 기반 = RBAC. 군사용 = MAC.
"MAC의 대표적인 구현 형태는 ACL" → ✗ ACL = DAC의 구현 형태.

4
시스템 콜 (System Call)
★★ 2016 국가직 출제
시스템 콜 정의

운영체제는 이중 모드(Dual Mode)로 되어 있는데, 이는 사용자 모드(User Mode)와 커널 모드(Kernel Mode, 또는 운영체제 실행 모드)로 구분됨. 사용자는 특권 명령을 사용할 수 없으며, 이러한 사용자가 운영체제에게 작업을 수행하게 되는데, 이를 시스템 콜(System Call)이라 한다. 즉, 시스템 콜은 실행 중인 운영체제에 요청하는 것이다. 입출력 제어를 운영체제(OS)에게 요청하여 사용자로부터 분리되는 운영체제의 기본 명령이다.

1
보안 운영체제 (Secure OS)
★★★ 2022 국가직
보안 OS 정의

보안 운영체제(Secure OS)는 기존 운영체제에 내재된 보안상의 결함으로 인한 각종 침해로부터 시스템을 보호하기 위하여, 운영체제 내에 보안 기능을 통합시킨 보안 커널(Security Kernel)을 추가적으로 이식한 운영체제. 보안 커널을 통하여 사용자의 모든 접근 행위가 안전하게 통제됨.

2
보안 시스템 설계 7원리
★★
1
소규모화 (Economy of Mechanism)
보안 메커니즘은 가능한 소규모로, 단순하며 간결하여야 한다. 충분한 분석·시험·증명이 가능해야 한다.
2
Fail-safe Defaults (보안 경제성)
접근에 대한 기본 결정은 접근 거부(Denial)이어야 한다. 허가가 있어야만 접근 허용.
3
개방형 설계 (Open Design)
보안 메커니즘은 비밀로 유지하는 것에 의존하지 말고 공개적으로 설계. 많은 검토를 통해 보안 공개적 검증 가능.
4
완전한 조정 (Complete Mediation)
모든 접근은 완전히 통제되어야 한다. 직접 접근이나 접근 통제를 교묘히 우회하려는 접근 모두 통제.
5
최소 권한 (Least Privilege)
접근에 대한 기본 허용은 최소 허용. 작업에 필요한 최소한의 권한만 부여.
6
권한 분리 (Separation of Privilege)
접근에 대한 권한은 2개 이상의 조건을 충족해야 한다. 물리적·시간적·논리적 분리 포함.
7
최소 공통 메커니즘 (Least Common Mechanism)
공유되거나 공통적인 접근 경로를 최소화. 사용 용이성을 위해 보안 희생 금지.
3
참조 모니터 · 보안 커널 · TCB
★★★ 2024 국가직
개념정의핵심 특성
참조 모니터
(Reference Monitor)		 주체(Subject)와 객체(Object) 사이의 모든 접근을 통제하는 추상적인 기계(Abstract Machine). 안전한 운영체제의 핵심 보안 모듈. ① 격리성(부정 조작 불가) ② 완전성(항상 호출·회피 불가) ③ 검증 가능성(소규모·분석 용이)
보안 커널
(Security Kernel)		 참조 모니터를 구현한 것. 일반 운영체제에 포함되어 있는 보안 기능을 향상시키기 위해 사용되는 것으로 참조 모니터를 수행함. 모든 접근 요청에 대해 검사하여야 하며, 변경으로부터 보호되고 검증 가능해야 함. 통합 커널·마이크로 커널 방식 존재.
TCB
(Trusted Computing Base)		 컴퓨터 시스템(HW·FW·SW) 내의 모든 보호 메커니즘의 총체. 보안 커널을 포함한 시스템 전체 보안 메커니즘. 운영 TCB = 기본적인 보호 환경 구축 + 신뢰성 있는 시스템 부가 서비스 제공. 보안 정책 적용 능력은 오직 TCB 내의 메커니즘에 의존.
보안 커널 설계 방식 2종: ① 통합 커널(Monolithic Kernel) — 시스템 콜(Function Call) 통하여 하드웨어 자원 이용. 보안 기능이 크고 복잡해질 수 있음. ② 마이크로 커널(Micro-kernel) — 크기를 줄이고 최소 기능만 갖는 방법. 프로세스 관리 서버·파일 관리 서버·메모리 관리 서버가 상호 간에 메시지 전달로 통신. 소규모에서 더 편한 보안을 위해 개발됨.
4
TPM · HSM
★★
구분TPM (Trusted Platform Module)HSM (Hardware Security Module)
정의신뢰 컴퓨팅 그룹(TCG)에 의해 산업체가 개발한 개념. 신뢰를 위한 하드웨어/펌웨어에서 동작하는 하드웨어 모듈.전자 서명 생성 비밀을 안전하게 저장·보관하고 기기 내에서 암호 연산이 가능한 하드웨어 장치.
탑재 위치개인용 컴퓨터 메인보드, 스마트 카드 등에 내장. TPM이 탑재되도록 인증된 하드웨어/소프트웨어와 함께 동작.스마트카드, USB 토큰 등 다양한 형태로 제작.
제공 기능① 인증된 부팅(Authenticated Boot) ② 증명(Attestation) ③ 봉인(Sealing)기기 내부 저장된 전자 서명 생성 비밀은 장치 복사 또는 재생성이 되지 않음. 서명 생성·전자 서명 생성·검증 가능.

Windows 커널 구조
★★

Windows는 커널 모드(Kernel Mode, 관리자 권한)와 사용자 모드(User Mode, 응용 프로그램 실행)의 이중 모드로 동작함. 커널은 인터럽트 처리·프로세스 관리·메모리 관리·파일 시스템 관리·프로그래밍 인터페이스 제공의 기본 기능을 하는 심장부임.

구성요소역할
HAL
(Hardware Abstraction Layer)		하드웨어를 위한 추상화 계층. 소프트웨어가 하드웨어에 원활히 접근하도록 도와줌.
마이크로 커널하드웨어와의 직접 통신을 담당하는 커널.
I/O 관리자입출력을 관리한다. 장치 드라이버를 관리한다. 응용 프로그램이 곧바로 하드웨어에 접근하지 못하게 제어.
객체 관리자파일·포트·프로세스·스레드 등 모든 것이 객체화되고 관리.
보안 참조 모니터 관리자시스템 자원에 접근하거나 수정함으로써 강제 보안 정책 임무 수행.
프로세스 관리자프로세스를 생성하고 규칙에 따라 관리.
LPC 관리자
(Local Procedure Call)		서로 다른 메모리를 공유하지 않으므로 프로세스 간 필요한 통신을 처리.
가상 메모리 관리자응용 프로그램에 따라 RAM을 할당하고 가상 메모리를 관리.
GDI 관리자이미지나 텍스트를 그리거나 폰트 처리.

Windows 인증 구조 — LSA · SAM · SRM
★★★ 매년 출제
구성요소핵심 기능모드암기 키워드
LSA
(Local Security Authority)		모든 계정의 로그인 검증, 시스템 자원·파일 접근 권한 검사. 로컬·원격 모두 해당. 이름↔SID 매칭. SRM이 생성한 감사 로그 기록.사용자 모드로그인 검증, 로컬 보안 정책 집행
SAM
(Security Accounts Manager)		사용자/그룹 계정 정보에 대한 데이터베이스 관리. 로그인 입력정보↔SAM DB 비교하여 인증 여부 결정.사용자 모드계정 DB 관리, 인증 결정
SRM
(Security Reference Monitor)		SAM이 일치 확인 후 SRM에 알리면 SRM은 사용자에게 고유의 SID 부여. SID에 기반하여 파일/디렉터리 접근 허용 결정. 감사 메시지 생성.커널 모드SID 부여, 감사 메시지

SID 구조 예시: S-1-5-21-2823624781-484892517-3265479878-500
수정자(S) - 버전(1) - 권한(5: NT Authority) - 도메인 식별자(21-...) - RID(상대식별자). RID: 500=Administrator, 501=Guest, 1000이상=일반 사용자.

⚠함정 ★★★ — LSA·SAM·SRM 역할 혼동
"SAM = 보안 토큰(SID) 발급" → ✗ SID 발급 = SRM
"SRM = 사용자 모드에서 로컬 보안 정책 집행" → ✗ SRM = 커널 모드. 사용자 모드+로컬 보안 정책 = LSA

# 체인 내부 규칙 조작
# iptables -A INPUT -p tcp --dport 80 -j ACCEPT 체인에 새로운 규칙 추가(-A)

# iptables -R INPUT 1 -p tcp --dport 80 -j ACCEPT 어떤 지점의 규칙을 교환(-R)

형식: 텍스트 / 위치: /var/log/messages
lastlog
사용자별로 가장 최근에 로그인한 시간·접속 장소·사용자명·IP 주소 등을 기록.
형식: 바이너리 / lastlog 명령으로 조회
wtmp
처음부터 현재까지 사용자 로그인·로그아웃·시스템 재부팅 정보 기록. 모든 사용자의 로그인·로그아웃과 마지막 재부팅 시간 데이터 포함.
형식: 바이너리 / last 명령으로 조회
utmp
wtmp에 대한 대칭 관계는 없음. 현재 로그인한 사용자에 대한 상태 정보를 집중적으로 기록.
형식: 바이너리 ⚠텍스트 아님 / who, w 명령으로 조회
btmp
실패한 로그인 시도 정보를 기록. 비밀번호를 틀렸을 때 등.
형식: 바이너리 / lastb 명령으로 조회
pacct
시스템에 로그인한 모든 사용자가 로그아웃할 때까지 수행한 프로그램 정보와 사용 내역 기록. 해킹 피해·백도어 설치 여부 파악 가능.
형식: 바이너리
sulog
root나 일반 사용자에서 다른 사용자로 전환 시 사용할 수 있는 su 명령에 대한 로그. 날짜·시간·성공(+)·패배(-)·사용한 터미널·사용자 정보 기록.
형식: 텍스트
history
침해 시스템 분석 시 불법 사용자나 root의 history를 분석하면 어떤 활동을 했는지 확인 가능. acct/pacct에서 기록되지 않는 명령의 argument까지 확인 가능.
형식: 텍스트 / ~/.bash_history
secure
Telnet이나 FTP를 거치는 PAM 인증 관련 로그. sudo·su·SSH 등 인증 기록 저장.
형식: 텍스트 / /var/log/secure
dmesg
시스템이 부팅할 때 커널에서 에러 로그 기록. 부팅 시 하드웨어 감지 메시지.
형식: 텍스트 / dmesg 명령으로 조회
syslog
사용자 관련 로그 및 커널·각종 데몬에서 발생된 로그를 포함. rlogin·ftp·finger·telnet·pop3 등에 대한 실패 기록. 발생 시 가장 먼저 업데이트됨.
형식: 텍스트 / /var/log/syslog
httpd access_log
/ error_log
웹 서버에 대한 액세스 및 에러 로그. DDoS 공격 등에 대한 액세스 로그 분석 가능.
형식: 텍스트 / /var/log/httpd/
xferlog
FTP를 통해 전송되는 모든 파일에 대한 로그 저장. 접속 IP·파일명·전송방향(송수신) 등 포함.
형식: 텍스트
loginlog
로그인 시도 시 5회 이상 실패한 경우 기록. (Solaris 전용, Linux에서는 btmp 사용)
형식: 텍스트
⚠함정 ★★★ — 로그 파일 역할·형식 혼동 (2015 국가직·2023 국가직 출제)
"loginlog = FTP 파일 전송 내역" → ✗ loginlog = 5회 이상 실패 로그인 / FTP 전송 = xferlog
"xferlog = 익명 로그인 시도 내역" → ✗ xferlog = FTP 파일 전송 내역
"utmp = 텍스트 형태로 기록" → ✗ utmp = 바이너리 형태. wtmp·btmp·utmp·pacct 모두 바이너리.
📋 로그 형식 암기 (바이너리 vs 텍스트)
바이너리wtmp·btmp·utmp·pacct·lastlog → 모두 바이너리. 전용 명령어로 조회.
텍스트messages·sulog·xferlog·loginlog·history·secure·dmesg·syslog·httpd → 텍스트. cat/grep으로 직접 열람 가능.
xferlogFTP 전송 내역. 전송 시각·IP·파일명·방향(o=송신, i=수신)·사용자명 포함.
loginlog5회 이상 실패한 로그인. (Solaris). 리눅스 = btmp.

연도순
📄 2016 국가직 9급 정보시스템보안 · 시스템 콜 빈칸★★★
운영체제는 이중 모드(Dual Mode)로 되어 있는데, 이는 사용자 모드와 커널 모드로 구분된다. 사용자는 특권 명령을 사용할 수 없으며, 이러한 사용자가 운영체제에게 작업을 수행하게 되는데, 이를 ( )라 한다.
① 시스템 관리(System management)
② 시스템 콜(System call)
③ 프로세스 관리(Process management)
④ 스케줄링(Scheduling)
정답 ② — 시스템 콜(System Call)은 사용자 모드 프로그램이 커널 모드의 기능을 요청하는 인터페이스. 입출력 제어를 운영체제(OS)에게 요청하여 사용자 영역으로부터 분리되는 운영체제의 기본 명령어.
📄 2015 국가직 9급 · 로그 파일 역할 매칭 오답★★★
유닉스 로그 파일에 대한 설명으로 바르게 연결한 것은?
ㄱ. history — 사용자가 했던 명령 내역
ㄴ. sulog — su 명령어 사용 내역
ㄷ. xferlog — 익명 로그인 시도 내역
ㄹ. loginlog — FTP 파일 전송 내역
① ㄱ, ㄴ, ㄷ, ㄹ 모두 맞음
② ㄱ, ㄴ만 맞음 (ㄷ·ㄹ 바뀜)
③ ㄴ, ㄷ만 맞음
④ ㄷ, ㄹ만 맞음
정답 ② (ㄱ·ㄴ 맞음, ㄷ·ㄹ 틀림) — ㄷ xferlog = FTP 파일 전송 내역. ㄹ loginlog = 5회 이상 실패한 로그인 내역. ㄷ·ㄹ이 서로 바뀌어 출제됨. 반드시 xferlog=FTP전송, loginlog=실패 로그인으로 암기.
📄 2016 국가직 9급 · chmod 751 권한 값★★★
다음 접근 권한으로 옳은 것은? chmod 751 test.c
① -rwxr-x--x (정답과 동일하나 표기 오류)
② -rwxr-x--x
③ -rwxrwx--x
④ -rwxr-xr--
정답 ② — 751 = 7(111=rwx) / 5(101=r-x) / 1(001=--x). 맨 앞 - = 일반 파일. 결과: -rwxr-x--x.
📄 2015·2022 국가직 · SRM = SID 부여 + 감사 메시지★★★
다음에서 설명하는 윈도우 인증 구성 요소는?
• 사용자의 계정과 패스워드가 일치하는 사용자에게 고유의 SID를 부여한다.
• SID에 기반을 두어 파일이나 디렉터리에 대한 접근 허용 여부를 결정하고 감사 메시지를 생성한다.
① LSA(Local Security Authority)
② SRM(Security Reference Monitor)
③ SAM(Security Account Manager)
④ IPSec
정답 ② — 키워드: "SID 부여" + "감사 메시지 생성" = SRM. SRM은 커널 모드에서 실행. LSA=로그인 검증. SAM=계정DB 관리.
📄 2023 국가직 9급 · passwd + SetUID + /etc/shadow★★★
(가)~(다)에 들어갈 내용을 바르게 연결한 것은?
일반 사용자가 (다)가 설정된 (가) 명령어를 실행하면 해당 프로세스는 일시적으로 파일 소유자인 관리자(root)의 권한을 얻게 되어 관리자만 접근할 수 있는 (나) 파일에 접근하여 비밀번호를 수정할 수 있다.
① (가)passwrd (나)/etc/shadow (다)SetUID
② (가)passwd (나)/etc/shadow (다)SetUID
③ (가)passwd (나)/etc/passwd (다)SetGID
④ (가)passwd (나)/etc/shadow (다)SetRID
정답 ② — 명령어 = passwd(passwrd 아님). 파일 = /etc/shadow. 권한 = SetUID. "SetRID"는 존재하지 않음.
📄 2023 국가직 9급 · utmp 바이너리 형태★★
유닉스/리눅스 시스템의 로그 파일에 대한 설명으로 옳지 않은 것은?
① utmp 로그는 특정 시간에 로그인한 사용자의 정보를 텍스트 형태로 기록한다.
② wtmp 로그는 사용자의 로그인·로그아웃·시스템 재부팅 정보를 바이너리 형태로 기록한다.
③ su 로그는 su 명령어 수행에 따른 권한 변경 시도 및 변경 정보를 텍스트 형태로 기록한다.
④ pacct 로그는 시스템에 로그인한 모든 사용자가 수행한 프로그램의 정보를 바이너리 형태로 기록한다.
정답 ① — utmp는 바이너리 형태. "텍스트"가 오답. wtmp·btmp·utmp·pacct·lastlog 모두 바이너리. 텍스트 로그: sulog·xferlog·syslog·history.
📄 2024 국가직 9급 · i-node에 파일명 없음★★★
유닉스 파일 시스템의 i-node 정보에 해당하지 않는 것은?
① 소유그룹
② 파일 타입
③ 파일명
④ 접근권한
정답 ③ — 파일명(File Name)은 i-node에 저장되지 않는다. 파일명은 디렉터리에 별도 저장되고 i-node 번호와 연결됨. i-node에는 파일 타입·접근권한·소유자(UID)·소유그룹(GID)·파일크기·링크수·시간정보·데이터블록 포인터가 저장됨.
📄 2025 국가직 9급 · chmod 1111 = Sticky Bit★★★
다음 명령을 수행한 후 '/directory'에 부여된 권한은? chmod 1111 /directory
① Read
② SetGID
③ SetUID
④ Sticky Bit
정답 ④ — chmod 1111 → 첫 자리 1 = Sticky bit. 4xxx=SetUID, 2xxx=SetGID, 1xxx=Sticky. 나머지 111 = --x--x--x. 결과: --x--x--t.

참조 모니터주체→객체 접근 통제. 3특성: 격리·완전성·검증가능

  • "SRM = 사용자 모드 + 로컬 보안 정책 집행" → ✗ (그건 LSA, SRM=커널 모드+SID부여)
  • "SetGID = chmod 1755" → ✗ (SetGID=2xxx, 1xxx=Sticky)
  • "utmp = 텍스트 형태로 기록" → ✗ (바이너리)

  • "i-node에 파일명 저장" → ✗ (파일명은 디렉터리에 별도 저장)
